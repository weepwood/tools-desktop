## 二、背景与目标

**背景**：用户需要把一个大视频按目标大小切成多个连续可播放的小段（如邮件附件限制、网盘单文件上限），且要求**无损**（`-c copy` 不重编码）。依赖本地 FFmpeg 的 segment muxer。

**要解决的问题**：
1. 按大小切分不能靠纯字节切（会切在关键帧外导致片段无法播放），需用 segment 时间 + 校验实际大小。
2. 关键帧间隔过长时，单靠缩短时间重试也要保证至少两段且不超限。
3. 断电/取消不能留下半文件污染最终目录（源文件绝不修改）。

**成功指标与口径**：
- 切分成功率 = 生成 ≥2 段且每段 ≤ 上限的完成任务数 ÷ 总切分任务数（目标 ≥95%）。
- 源文件零修改率 = 切分无论成败源文件大小/mtime 不变的比例（目标 100%，已实现写前/后校验）。

## 三、名词与术语定义

| 术语 | 定义 |
|------|------|
| 分片上限 `maxSizeGb` | 用户设定，换算为字节（0.00001–10000 GB） |
| segment muxer | FFmpeg 按时间切片并 `-c copy` 无损封装 |
| 计划时长 `planDuration` | `duration × maxBytes/sourceBytes × 0.72` 安全系数 |
| attempt | 单次切分尝试，超限则时长减半重试，最多 9 次 |
| 清单 `split-manifest.json` | 记录分片 index/name/size，供合并校验 |

## 四、需求范围

**包含**：选视频、设上限、无损切分、自动重试（时长减半）、输出目录自动分配、分片清单、合并（ffconcat）、中断恢复、源文件保护。
**不包含**：重编码压缩、音频分离、字幕处理。

## 五、方案对比与选型说明

| 方案 | 对比 | 结论 |
|------|------|------|
| 切分方式 | 纯字节切 vs segment 时间 + 大小校验 | **segment 时间 + 校验**（避免非关键帧断点） |
| 超限处理 | 报错 vs 时长减半重试（最多 9 次） | **自动重试**（已落地） |
| 源保护 | 直接输出 vs attempt 临时目录 + 原子 rename | **临时目录 + 原子 rename**（已落地，源绝不改） |
| 合并 | 手动 vs ffconcat 无损合并 | **ffconcat 合并**（已落地） |

推荐：维持现状。后续演进：关键帧间隔过长时给更明确的可选提示（重编码兜底）。

## 七、功能需求

**FR-01 参数与源校验**
- 描述：`split` 校验 `maxSizeGb`（0.00001–10000 GB）、视频为绝对路径普通文件、可读时长；源 ≤ 上限则直接 `skipped`。
- 验收：Given 上限 0，When 提交，Then 拒绝；Given 源 ≤ 上限，When 提交，Then 状态 skipped 且不调用 ffmpeg。

**FR-02 无损切分 + 自动重试**
- 描述：用 segment muxer `-c copy` 切分；若某段 > 上限或仅生成 1 段，删 attempt 目录、时长减半重试，最多 9 次或时长 <0.2s 报错。
- 验收：Given 关键帧间隔过长导致单段超限，When 重试，Then 多次后成功或明确报错「无法在不重编码下生成至少两段」；Given 成功，Then 每段 ≤ 上限且 ≥2 段。

**FR-03 源文件保护**
- 描述：切分全程在 `attempt-N` 临时目录进行，确认后 rename 到最终目录；源文件大小/mtime 在前后一致才确认；任何失败/取消只删 attempt 临时目录，**源永不修改**。
- 验收：Given 切分失败，When 结束，Then 源文件大小/mtime 不变；Given 取消，When 结束，Then 仅 attempt 临时目录被清理。

**FR-04 输出目录与清单**
- 描述：`allocate` 自动分配 `<名>_分片_N` 目录；完成写 `split-manifest.json`（index/name/size）。
- 验收：Given 切分完成，When 检查输出目录，Then 含分段文件与 manifest。

**FR-05 合并**
- 描述：`merge` 按 manifest 用 ffconcat 无损合并回单文件（保留原始分片），校验清单与任务记录一致、分片未被移动/替换。
- 验收：Given 已完成且 ≥2 段任务，When 合并，Then 生成 `<名>_合并.<ext>` 且原始分片保留；Given 分片被改动，When 合并，Then 拒绝。

**FR-06 中断恢复**
- 描述：`recover` 把 `running` 任务标 `interrupted`，提示临时文件保留在 attempt 目录需手动清理。
- 验收：Given 遗留 running 任务，When 启动 recover，Then 标 interrupted。

## 八、非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 复用 FFmpeg segment；进度按 out_time 估算 |
| 安全 | 源文件只读、零修改；输出目录独占创建 |
| 兼容 | 输出格式按源扩展名映射（mp4/mkv/mov/webm） |

## 九、业务流程与状态流转

**任务状态机**：`running` → `completed` / `skipped` / `cancelled` / `failed`；合并 `mergeStatus` 独立。
主流程：probe → allocate → 循环 attempt（切分→校验大小→超限重试）→ 原子 rename → 写 manifest → save(completed)。

## 十、数据与埋点需求

- 核心文件：`split-tasks/<id>.json`（schemaVersion/maxSizeGb/sourceBytes/parts/outputDir/status）；`split-manifest.json`。
- 埋点建议：切分任务数、平均段数、重编码兜底触发率（当前仅 logger）。

## 十一、权限与安全要求

- 仅读取用户选定视频；输出到用户选定/默认目录。
- 源文件只读打开，绝不写入。
- 无网络。

## 十二、异常处理清单

| 场景 | 处理 |
|------|------|
| 上限非法/超范围 | 拒绝 |
| 无法读时长 | 拒绝（不能安全按大小切） |
| 关键帧过长致无法分段 | 重试耗尽后明确报错，源未改 |
| 切分期间源变化 | 拒绝确认结果 |
| 用户中止/失败 | 仅删 attempt 临时目录，源不变 |
