# HALO 顶栏设计说明

> 本文回答两个问题：顶栏该多高、该放什么。
> 尺寸部分已实现（52px → 44px）；功能部分是设计方案，未实现。

---

## 1. 空间预算（先算账，再谈功能）

默认窗口 1180×780，左栏 240px，右侧簇固定：

| 区域 | 宽度 | 现状 |
|---|---|---|
| 左簇（面板开关 + 品牌） | 约 92px（侧栏展开时占位 240px） | 已满 |
| **中段（可拖拽区）** | **约 730px** | **纯空白** |
| 右簇（3 面板开关 + 3 窗口按钮） | 约 196px | 已满，且不可挤压 |

结论：中段是全界面最大的一块闲置资源。功能应该加在这里，而不是挤左右两簇。

另一个约束是**高度**。52px 时按钮上下的留白偏松；收到 44px 后，26px 高的按钮上下各留 9px，既够点又不浪费，一屏能多出 8px 内容高度。

---

## 2. 五条设计规则

1. **只放全局且随时可用的东西。** 预扫描、开始洗码、导出这类动作永远留在页面内——它们是"当前上下文"的操作，放进顶栏就会变成"我到底在操作哪个页面"的困惑。
2. **中段最多一个主入口 + 一个状态件。** 超过两个，顶栏就从"导航层"退化成"工具栏"，窗口按钮会被挤得难找。
3. **右簇位置锁死。** 任何新增控件不得推动最小化/最大化/关闭按钮；它们是肌肉记忆。
4. **每个新控件必须有键盘路径**（快捷键 + Tab 可达 + 有 tooltip 显示快捷键）。
5. **窄窗自动折叠**，不做横向滚动：< 960px 时命令入口退化为图标、胶囊只留进度环。

## 3. 候选功能与取舍

| 候选 | 解决什么问题 | 成本 | 冲突 / 风险 | 结论 |
|---|---|---|---|---|
| **A. 命令面板（⌘K）** | 4 个工作区 + 设置 + 历史都要点侧栏才能到；历史只能翻列表 | 中 | 需要一个索引层（工作区静态表 + `searchSettings` 复用 + `listHistory`） | **P0** |
| **B. 任务胶囊** | 任务在跑时切到别的页就看不到进度、也停不了，只能回到洗码页 | 低 | 需要把进度广播进 `task-status`（见 §6） | **P0** |
| C. 当前范围面包屑 | 洗码选中的目录很长，被压缩在左栏小字里 | 低 | 洗码的 `rootPath` 是页面内持久状态，要提升为共享 store | P1 |
| D. 结果/通知中心 | 最近一次任务成功/失败数，比翻历史快 | 中 | 与「历史与恢复」功能重叠，容易做成第二套历史 | P1 |
| E. 主题快切 | 切深浅色要进设置 | 极低 | 占一个按钮位；更适合放进命令面板 | P2（并入 A） |
| F. 专注模式 | 一键收起三个面板 | 低 | 已有三个面板开关，这只是宏 | P2（改用快捷键） |
| G. 拖放到顶栏 | 文件直接拖进来 | 中 | `-webkit-app-region: drag` 区域收不到 drop 事件，要划 no-drag 区，容易误触 | 不做 |
| H. 帮助/快捷键速查 | 记不住快捷键 | 低 | 设置页已有 | 并入 A（搜 `?`） |

**不做**：更新提示（本机工具无自动更新）、缩放控件（桌面工具少见）、账户（本应用无登录）。

## 4. 推荐布局（方案 B）

```
[▤] (◯) HALO   [🔍 搜索功能、历史或设置        ⌘K]   …   [◐ 洗码 128/320]  [▤][▥][▤]  [−][□][×]
 └─ 现有 ─┘     └────────────── 新增 A ──────────────┘      └─ 新增 B ─┘   └─ 现有 ─┘  └ 现有 ┘
```

### A. 命令面板入口

- 外观是个**看起来像输入框的按钮**（不是真输入框），点击或 `Ctrl/⌘ K` 打开面板；不抢焦点、不参与 Tab 顺序里的输入。
- 面板内容：工作区（洗码/截图/切分/历史）、最近目录、历史任务（标题＝目录名 + 时间）、设置项（复用 `settingsSearch`）。
- 排序：最近使用 > 完全匹配 > 模糊匹配。默认高亮第一项，回车执行，Esc 关闭。
- 为什么不做成"顶栏常驻真输入框"：顶栏是拖拽区，常驻输入框会和拖窗手势打架，而且会让顶栏永远处于"待输入"的紧张状态。

### B. 任务胶囊

只在有任务时出现（无任务时整块消失，不留空位）。

| 状态 | 显示 | 交互 |
|---|---|---|
| 运行中 | 环形进度 + `洗码 128 / 320` | 悬停展开「停止」，点击跳到该任务所在页 |
| 停止中 | 环形虚线 + `正在停止…` | 按钮禁用 |
| 完成 | 短暂显示 `✓ 成功 318 · 失败 2`（3s 后淡出） | 点击跳到历史 |
| 失败/异常 | 红色环 | 点击跳到历史并展开该条 |

关键点：**进度环用 `--halo-action-color`，完成态用 `--color-success`，异常用 `--color-danger`**——与页面内的状态点同色，不引入新语义。

---

## 5. 状态与动效

| 场景 | 规范 |
|---|---|
| 胶囊出现 | 从右滑入 8px + 淡入，220ms `ease-emphasized` |
| 胶囊消失 | 淡出 150ms，不滑出（避免和窗口按钮抢视线） |
| 进度变化 | 环的 `stroke-dashoffset` 220ms 线性；数字用 tabular-nums 不抖动 |
| 面板打开 | 中段整体向左压缩，命令入口宽度 320 → 200，`width` 用 max-width 过渡 |
| 窄窗折叠 | < 960px：命令入口成 26px 图标；< 820px：胶囊只留环 |
| reduce-motion | 全部改为瞬时切换（沿用全局规则） |

## 6. 实现落点（给动手时看的）

- **胶囊数据**：`electron/main.cjs` 的 `broadcast('task-status', status())` 目前只有 `{running, kind, cancelling}`。三个引擎（engine/split/video）本来就在 `send({completed,total,currentFile})`，把这三个值也存进 `active` 并一起广播即可，一处改动、三处免费。
- **命令面板**：新增 `src/shell/CommandPalette.tsx`，用 `dialog` 之上的一层 overlay（`--z-overlay`）；索引用 `settingsSearch` 的现有实现 + `listHistory`；快捷键走 `lib/shortcuts.ts` 的注册表（新增 `open-command`）。
- **胶囊组件**：`src/shell/TaskPill.tsx`，订阅已有的 `TaskStatusProvider`，不新增 provider。
- **窄窗规则**：用 `container-type: inline-size` + `@container` 写在 `TitleBar.css` 里（与洗码页一致的做法），不要用 JS 监听 resize。

---

## 7. 实施顺序

1. **P0-1** 任务胶囊（成本最低、解决"切页就丢失进度"这个真痛点）
2. **P0-2** 命令面板（把 4 个工作区 + 历史 + 设置串成一个入口）
3. P1 面包屑（需要先把 `rootPath` 提升为共享状态）
4. P1 结果中心（先定义好与"历史"的边界，否则会做成两套）
5. P2 主题快切 / 专注模式（并入命令面板即可，不占顶栏位置）
